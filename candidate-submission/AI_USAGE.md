Copilot was asked to set up and implement the assessment project using React with TypeScript and Django REST Framework, honoring the approved backend stack change. It generated/modified the repository structure, frontend workflows, Django/Celery application code, tests, local Compose services and technical documentation. An initial frontend dependency audit identified development-tool advisories; the toolchain versions were updated and the audit then reported zero vulnerabilities. I reviewed the implementation and ran the PostgreSQL-backed tests myself with Docker Compose (`docker compose exec api python manage.py test apps`: 38 tests, OK). I did not give any AI tool production credentials or confidential third-party material.

Claude Code was then used to review the Copilot-generated baseline against the assessment brief and to improve it:

1. **What I asked for:** an audit against `docs/ASSESSMENT.md`; a cleaner backend structure; fixes for the defects the audit and test runs found; a browser-level test of the running app; help joining and captioning my screen-recording clips.
2. **What was generated or substantially changed:**
   - The single `apps.core` app was split into domain apps, with transactional logic moved into service modules and fresh per-app migrations.
   - Work-order references are now generated by the server; a reference collision is retried inside a savepoint.
   - Create/update retry once when PostgreSQL aborts them as a deadlock victim on the scheduling constraint, so the loser gets 409 instead of 500.
   - User management is owner-only at the viewset level, validated by serializers, with the acting owner re-checked under the organization lock.
   - The SSE endpoint accepts `Accept: text/event-stream`; the dashboard listens for the named events.
   - Frontend fixes: stuck list loading, activity history after saving, error messages, upload hidden from technicians, change details in the history.
   - The status-change note is now kept in the audit entry.
   - Test fixes: two wrongly written tests, leaked thread connections at teardown, test settings isolating cache, Celery and storage.
3. **What I changed or decided:** I chose random server-generated references over a per-organisation counter; kept deactivation instead of user deletion; and recorded every clip of the walkthrough myself.
4. **How I verified it:** I ran the backend suite in Docker Compose (38 tests, OK) and the frontend test, lint and build commands. Claude ran each test separately before and after the restructure to show identical results, stress-ran the concurrency tests, probed suspected defects against a real database, and ran a 29-step headless-browser test of the full stack. Known remaining gaps are listed in `TECHNICAL_NOTES.md`.
5. **Rejected output:** a per-organisation sequential counter for references (it would make creates in one organisation run one at a time); blurring the documented local sample password in the recording.
